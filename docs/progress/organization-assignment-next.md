# 组织成员关联分页：实施约束

此处保留实施前约束；当前实现/实际证据见 ../organization-assignment.md / ../validation.md。基于 0.20.0 / 1df29b3，修复关联弹窗只列前 100 位成员、组织选项依赖主列表已加载页的限制。复用已有 members/organizations/assign API，不新增权限、迁移或 API；角色选择器保留上一节点。

- 独立弹窗显式逐次加载 25 个成员和组织，显示已加载数而非总量；只提供当前已读取 active 成员的选项，不自动默认选中目标。使用明确确认后一次 PUT，组织归属不授予角色。
- 成员页复用固定 Member 投影与 authz ETag；组织页使用固定 Organization 投影、org ETag 和根 ID，两个版本不能混用。跨页版本/字段/大小/ID/游标不一致与读取失败清除选择；结构变动提示重读，真实 401 要求重新授权。
- 写入前置条件必须是成员读取得到的 authz ETag，不是结构 org ETag 或页面旧缓存；API 在事务内检查当前 organizations.write、有效成员/组织、近期 MFA 和版本。重复/未知回包不自动重试；丢包后退出原表单并核对实际直属成员。
- 读取可关闭/取消；同步 pending、AbortController、请求代数、当前 URL context 和组件卸载阻止迟到结果。写入中禁止关闭；组件/空间离开后的结果不显示到新空间。用户变更目标后原确认失效。
- 主页面沿用 organizations.read 导航，以及 organizations.write 和 members.read 的关联入口；不因组件存在增加 API 管理能力。大人口/组织夹具限定新建已核验 owner、非演示空间、无凭证合成成员与完整闭包数据，清理按本轮精确 ID/引用检查，不宽泛按前缀删除。

验收覆盖超过 100 成员和 50 组织的末页真实关联/审计与无角色变化、可用的普通委托流程、关闭/重开/换空间、权限/结构变化、畸形/依赖失败和已提交丢包不重发。原创建/移动上级选择器的进一步改进不在首个关联切片。完成实际验收/完整资料/离线编译/演示保护后再推主干；CI/GCP/部署由 SRE 负责。
