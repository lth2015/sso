# 外部机器服务接入的原始实施约束

基于 0.14.0 的独立机器资源样例，下一步应让外部业务服务有可复用、可验收的接入代码。此记录保留实施前约束；当前实现和验收见 ../external-machine-integration.md / ../validation.md，没有与 marketstars 联调；marketstars 的实际仓库/本地入口对接仍由后续明确集成任务处理。

首个 SDK 可限定为 Go 服务端的在线机器身份验证器：业务服务收到入站 Bearer 后，以配置好的 SSO 原点与预期 application ID 调用机器 identity 资源，获取主库校验后的 tenant/SP/credential。每次验证都在线检查，不缓存成功权限，不在失败时退化为解码或仅离线验签。业务服务仍自行决定具体业务资源权限；machine:invoke 不等于任意平台或业务管理员权力。

配置只接受可信部署代码提供的固定 HTTPS 原点；请求参数不得选择主机、路径、issuer/JWKS 或回调。仅对明确的当前本地回环入口允许 HTTP，并保持 API Host 校验；不能为调试允许任意 HTTP 主机。禁止重定向与 Cookie、受控超时/响应体大小、请求取消、响应字段/tenant/application/scope 检查；不返回原始响应或上游错误文本，不记录 Bearer。

测试应覆盖真实当前 Hydra 机器 token、实际在线资源验证、撤销即时拒绝、SP/应用停用恢复、错应用/租户/realm，以及受控 HTTP 超时/重定向/畸形/超大响应/伪造身份元数据。模拟传输边界与真实服务验收分别记录。机器凭证交换/缓存和自动业务写重试不属于第一 SDK 范围，避免把 secret 管理和业务重放隐含引入验证器。
