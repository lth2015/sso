# 角色绑定选择器分页：实施约束

基于 0.19.0 / 1a9d5aa，修复绑定选择器仅能使用前 100 位成员的限制。原角色配额仍为每空间 100；本切片不提高配额、不改变角色服务或权限模型。

- 复用现有 members/roles 的主库分页与绑定 API，选择器显式逐次加载 25 项，保留已选成员/角色。主成员列表后页的行操作可直接打开该成员；自然分页到该成员时不能重复。
- 角色元数据/绑定版本使用 authz ETag；前后读取不一致、畸形/重复/倒退/不推进的分页、未知字段与依赖错误清除本次待提交选择。没有授权缓存或自动重试写入；最终写入仍由服务端检查当前权限、最近 MFA 与精确 ETag。
- 读取中可以关闭/取消，AbortController 与请求代数、URL 当前上下文及组件卸载阻止迟到结果。更换目标成员先清除旧绑定/旧角色，当前新绑定读取完成前禁写；写入中维持一次提交与禁用关闭。
- members.read 被显式 deny 的 owner 不列举成员，保留只选择自己、读取自己绑定/恢复角色管理的既有入口。普通成员不能借此取得角色管理能力。
- 大人口测试只在新建且已核验所有权、非演示空间加入无 alias/无凭证的合成用户/成员与空策略角色；真实登录/授权/API/BFF 不伪造。清理先保护保留版，再逐个校验本轮精确 ID/归属/未关联凭证与角色用途，不按名字或前缀广泛删除。

实际验收包括超过 100 的末页真实绑定、角色第二页、后页行目标、读中关闭/重开/换空间、畸形/失败清空及 owner 自己的拒绝恢复入口。通过后同步完整资料/离线验收、复核演示及迁移摘要再提交。CI/GCP/部署仍由 SRE 负责；此约束记录不等于已交付证据。
