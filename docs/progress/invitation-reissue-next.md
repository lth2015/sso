# 邀请凭证更新：下一切片约束（尚未实施）

基于审计导出 0.16.0 之后继续完善邀请生命周期。本文件是实施前约束，不能作为功能已经可用的证据；先完成 0.16 主干检查点及文档/完整验收，再实施。

- 解决未关闭邀请的凭证遗失/过期：显式更新一次性凭证，旧凭证立即无效，新凭证有效 24 小时，目标邮箱与邀请/空间 ID 不由本次请求改写。已接受或撤销的邀请不能复活。
- 新增 invitation detail 受控元数据和租户/资源/版本绑定 ETag。更新需要当前 invitations.manage、近期 MFA、空 JSON body 与精确 If-Match；并发更新最多一项成功，旧版本返回 412。不改动既有 API 的创建/撤销调用方式。
- 版本用新增迁移提供，不修改已应用 001–009。接受、撤销和凭证更新的实际转换同事务递增 invitation revision；默认旧数据 revision=1。旧读取 DTO 保持不变，详情不恢复 proof/digest。
- 同一主库事务锁定当前权限及邀请，更新 digest/expiry/current creator 与 revision，写受控 invitation.reissued 审计/outbox。接受仍复查当前管理者资格，不以原创建者离任绕过权限。明确接受与更新的并发结果；原 proof 在初始查找之后被更换时也只能受控拒绝，不能返回 SQL 原文或临时成功。
- 新 proof 使用独立随机 256-bit 材料，只在更新成功响应一次交付；业务库只存摘要。未知结果不自动重试或恢复明文，先读取详情/列表，必要时再次显式更新。API/BFF/OpenAPI/Playground 与实际用户界面一致。
- 控制台按当前空间/页面/请求代数管理详情与一次性结果；关闭、切换空间、取消读取或迟到响应不得重新显示 proof。确认旧凭证失效与安全转交后只发一次写入。不会把此功能称为“邮件已重发”：当前没有正式邀请邮件投递。
- 实际 MySQL 测试覆盖版本/过期/关闭/原子审计/并发接受与更新；真实 Bearer/BFF/浏览器覆盖当前权限、显式 deny、最近 MFA、wrong tenant、ETag、旧 proof 拒绝、新 proof 仅匹配邮箱可接受、丢包后不重试及秘密排除。新功能通过后再执行受影响的兼容回归、演示保护和完整文档导出。

不改动周五固定标签、原账号/密码/MFA/恢复码或长期配置/密钥；不介入 SRE 的 CI/GCP/部署。marketstars 的实际接入仍待独立联调，不从本地示例推断已完成。
